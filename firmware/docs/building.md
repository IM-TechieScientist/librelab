# Building and flashing

The repository contains two independent embedded projects:

- The root CMake project currently builds `librelab_pico` for Pico 2/RP2350A.
- `esp_firmware/` is an ESP-IDF project for ESP32-C3.

## RP2350 firmware

The commands in this section build the current RP2350A target. `PICO_BOARD=pico2`
selects the Pico 2 board definition, including `PICO_RP2350A=1`; it is not a
valid final board definition for a custom RP2350B PCB.

### Toolchain

The build requires CMake 3.13+, the Arm GNU embedded compiler, and a Pico SDK
checkout with submodules. Pico SDK 2.1.0 is known to build this snapshot.

Set the SDK path either in the environment:

```bash
export PICO_SDK_PATH=/opt/pico-sdk
```

or on the CMake command line:

```bash
cmake -S . -B build-pico2 \
  -DPICO_BOARD=pico2 \
  -DPICO_SDK_PATH=/opt/pico-sdk
```

### Configure and build

Ninja:

```bash
cmake -S . -B build-pico2 -G Ninja -DPICO_BOARD=pico2
cmake --build build-pico2 --target librelab_pico
```

Unix Makefiles:

```bash
cmake -S . -B build-pico2 -DPICO_BOARD=pico2
cmake --build build-pico2 --target librelab_pico -j"$(nproc)"
```

For diagnostic symbols:

```bash
cmake -S . -B build-debug -G Ninja \
  -DPICO_BOARD=pico2 \
  -DCMAKE_BUILD_TYPE=Debug
cmake --build build-debug --target librelab_pico
```

### Outputs

CMake places the main outputs at the top of the selected build directory:

| File | Purpose |
| --- | --- |
| `librelab_pico.elf` | Debugger and symbol-rich executable |
| `librelab_pico.uf2` | BOOTSEL drag-and-drop image |
| `librelab_pico.bin` | Raw binary image |
| `librelab_pico.hex` | Intel HEX image |
| `librelab_pico.dis` | Disassembly when generated by Pico SDK tools |
| `librelab_pico.elf.map` | Linker map |

### Flashing

BOOTSEL is the simplest method. Copy the UF2 to the mass-storage volume exposed
while BOOTSEL is held.

With `picotool`:

```bash
picotool load -f build-pico2/librelab_pico.uf2
picotool reboot
```

For SWD, use the `ELF` with OpenOCD, probe-rs, or your IDE. Probe and target
configuration varies, so follow the probe vendor’s RP2350 instructions.

### Clean rebuild

Build directories are disposable:

```bash
cmake --build build-pico2 --target clean
```

If CMake cached an incorrect SDK or board, create a new build directory rather
than editing the cache manually.

### Future RP2350B target

The future PCB needs its own Pico SDK board header and a separate build
directory. The board definition must select platform `rp2350`, set
`PICO_RP2350A` to `0` (the SDK's current spelling for the B package), and define
the actual flash, LED, and other board properties. A future configure command
will have this shape once `boards/librelab_rp2350b.h` exists:

```bash
cmake -S . -B build-rp2350b -G Ninja \
  -DPICO_BOARD=librelab_rp2350b \
  -DPICO_BOARD_HEADER_DIRS="$PWD/boards"
```

Creating that board header alone is insufficient: the ADC mapping, GPIO range
checks, fixed peripheral mappings, and PIO GPIO base also require the changes
listed in [RP2350B migration](rp2350b-migration.md). Until those changes and a
hardware test pass are complete, RP2350B is a planned target rather than a
supported build.

## ESP32-C3 bridge firmware

### Toolchain

Use ESP-IDF 5.1.x. The component lock records ESP-IDF 5.1.1 and mDNS component
1.2.5 for the verified snapshot.

Load ESP-IDF into the shell, then select the target:

```bash
. /path/to/esp-idf/export.sh
cd esp_firmware
idf.py set-target esp32c3
```

### Configure

Defaults live in `esp_firmware/sdkconfig.defaults`. Project-specific options are
under the `LibreLab ESP SPI bridge` menu:

```bash
idf.py menuconfig
```

The configurable values are the provisioning AP password, initial UDP
destination/ports, Pico-link SPI pins, READY pin, and serial statistics interval.
The provisioning password must contain at least eight characters.

### Build and flash

```bash
idf.py build
idf.py -p /dev/ttyACM1 flash
idf.py -p /dev/ttyACM1 monitor
```

Combined flash and monitor:

```bash
idf.py -p /dev/ttyACM1 flash monitor
```

Leave the monitor with `Ctrl-]`.

### Erase saved Wi-Fi credentials

Wi-Fi credentials are stored in NVS. To force provisioning again, erase flash
and reflash:

```bash
idf.py -p /dev/ttyACM1 erase-flash
idf.py -p /dev/ttyACM1 flash monitor
```

This destroys all ESP flash contents, including saved credentials.

## Build reproducibility notes

- Keep generated `build*`, `sdkconfig`, managed-component, and compiler output
  out of source control unless a project policy explicitly says otherwise.
- `dependencies.lock` pins the ESP component resolution.
- The root build uses the Pico SDK supplied by the developer; pin that SDK in
  the parent project or CI environment for reproducible binaries.
